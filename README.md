# Solyn

Solyn is a personal AI project knowledge assistant: a manual project/note workspace plus AI chat that prepares editable note drafts. Notes become project knowledge only after explicit user confirmation. Projects, notes and conversations are isolated by authenticated account; public registration is disabled.

Implemented through Phase 3: manual notes with revision/conflict protection, persisted Groq chat, durable draft previews, and atomic, idempotent note confirmation. Retrieval, source-grounded Q&A and citations are **not implemented yet**.

## Stack and layout

Bun workspace monorepo, originally generated by Better-T-Stack:

- `apps/web` — fullstack Next.js application, application services and tests.
- `packages/auth` — Better Auth configuration and controlled owner provisioning.
- `packages/db` — Drizzle/PostgreSQL schema, connection factory and migrations.
- `packages/ui` — shared UI primitives, Tailwind styles and tokens.

Chat uses Vercel AI SDK with Groq and `openai/gpt-oss-120b`. The model receives a schema-only `prepareNote` tool, never a note-writing capability.

## Development setup

Use **Bun 1.3.13** (`package.json`) and Node.js **22+** for the installed Next.js/AI tooling.

```sh
bun install --frozen-lockfile
bun run dev:web
```

Before starting the app, configure ignored local environment files according to `apps/web/.env.schema`: Better Auth URL/secret, the approved development database URL and Groq key. Keep credentials server-side. Follow the approved TLS/CA configuration; do not disable certificate verification.

The install `postinstall` generates ignored `src/env.ts` modules from both workspace environment schemas. After schema changes, use `bun run env:generate`. Schema code generation does not require runtime credentials. Tests inject dependencies and typechecks need the generated files, not live services. Code generation does not initialize runtime values; Varlock's framework integration or `varlock run` loads them. Bun automatic env loading is disabled in `bunfig.toml`.

Open [localhost:3001](http://localhost:3001). `bun run dev` starts all workspace development scripts. For controlled account setup, see [Owner provisioning](docs/OWNER_PROVISIONING.md); there is no public sign-up/bootstrap endpoint.

**Database setup is not automatic.** Obtain PM approval for the exact target and action before migrations, seeding, `db:push` or database writes. Review [migration history and baseline warnings](packages/db/src/migrations/README.md); never blindly apply the initial auth baseline. `bun run db:generate` generates migration artifacts, not database client/types, and does not apply them.

## Local feedback and PR verification

During implementation, run the affected test file and related regression tests, for example:

```sh
bun test apps/web/src/features/chat/client.test.tsx
bun test apps/web/src/features/workspace/note-confirmation.test.ts
bun run check-types
bunx oxlint
```

Use broader local checks for auth/ownership, persistence/recovery, schema or cross-cutting changes. For optional Git-based selection, `bun test --changed=origin/main` selects affected tests; a docs-only change can select none, and dependency selection is not a substitute for explicit regression tests or full CI.

[PR CI](.github/workflows/ci.yml) runs on pull requests targeting `main`: frozen-lockfile install (including environment type generation), the complete `bun test` suite, workspace typechecks and non-mutating Oxlint. Tests use mocks/scripted drivers, not Supabase or Groq. CI has no application secrets, database services or deployment jobs.

The initial workflow omits production build: a credentials-free build has not been established; Next.js loads required runtime configuration and downloads Google fonts. Use `bun run --filter web build` in an appropriately configured local environment. Do not weaken validation or add real CI credentials merely to make it pass. Offline tests/builds do not establish live PostgreSQL concurrency, provider compatibility or authenticated browser acceptance.

**Windows install note:** use the canonical checkout path rather than a Windows 8.3 short-path alias. Bun 1.3.13 can miscompute workspace paths through those aliases; a clean frozen install succeeds with the unchanged lockfile from the canonical path. No remote Actions result is claimed.

Formatting is separate:

```sh
bunx oxfmt --check README.md .github/workflows/ci.yml
```

Supply the files you changed. Existing historical Markdown has formatter differences; avoid unrelated whole-document formatting churn. **`bun run check` runs `oxlint && oxfmt --write` and modifies files**; it is not a read-only check. Inspect any formatting diff. `bun run build` builds all workspaces; `bun run check-types` checks all workspace TypeScript projects.
